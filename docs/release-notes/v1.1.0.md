# v1.1.0

Draft body for the first **published** GitHub release. It is written to be used
as `body_path` in `.github/workflows/release.yml` (see the note at the end): with
`generate_release_notes: true` GitHub composes notes from merged pull requests,
and this repository has none — every commit here is a direct push to `main`, and
the recent ones are all titled "Latest update". Auto-generated notes for this
release would therefore be a commit list, not the four facts the brief asks a
release to carry.

## What this is

Project Singularity is one static page that behaves like a browser-native
workspace: a collaborative editor on a hand-written CRDT, an in-browser C/C++
compiler, a WebGL2 engine, an end-to-end-encrypted messenger, a peer mesh, an
offline-first storage layer, an accessibility/i18n layer and hostile-environment
hardening.

- **Zero runtime dependencies.** `dependencies` and `devDependencies` are both
  empty, nothing in `src/` imports a package, there is no bundler and no
  framework. Node and Python are used by the measurement tools only.
- **Modules.** Eight scored modules — M1 87, M2 76, M3 93, M4 82, M5 78, M6 85,
  M7 66, M8 72 — totalling **639 / 1000** self-assessed. Three are complete
  (M1, M4, M6); five carry declared scope boundaries that name what they do not
  do. Two cross-cutting rows are measured separately (performance and
  reliability budget 88, integration and release discipline 69), and the SINGU
  AI assistant is unscored.
- **Tests.** **420 tests across 31 suites**, runnable in the browser from the
  deployed site itself. 412 are browser-eligible; 8 are Node-only. The bare-Node
  runner reports 390 pass and 30 browser-only skips, never as failures.
- **Live URL.** <https://ashrafularefin78-prog.github.io/PROJECT-SINGULARITY/> —
  one public URL, updated by every push to `main`.
- **Evidence.** Every number on the page is produced by a tool in this repo and
  archived in `docs/reports/`, now indexed as machine-readable data in
  [`docs/reports/measurements.json`](https://ashrafularefin78-prog.github.io/PROJECT-SINGULARITY/docs/reports/measurements.json)
  (19 measurements, 9 records). `node tools/check-docs.js` re-derives the
  published numbers from those artifacts and fails the build when a document
  drifts from them.

## Why the first release took three tags to publish

`v0.1.0` and `v1.0.0` were both cut on 22 October 2026 from commits that did not
contain `.github/workflows/release.yml`. A tag-push workflow only runs if the
workflow file is present **in the commit the tag points at** — not on the default
branch, and not later. So the workflow existed, had never run, and the releases
list stayed empty while the tags page showed two releases' worth of work.

The lesson is not "cut a tag harder": a tag is a pointer, and the pipeline that
publishes must be inside the thing it points at. This release is tagged from
`main` at a commit where the workflow is tracked, which is the smallest change
that makes the difference visible. The two older tags are left where they are —
they are honest records of what was built on that date, and rewriting them would
destroy the history that explains the gap.

## What changed since v1.0.0

- The documentation gate is fixed. `tools/check-docs.js` read
  `docs/reports/turn-relay.json`, an artifact that had never existed in the
  repository's history, so the CI job crashed instead of reporting. The claim is
  gone; `docs/LOAD_CHAOS.md` now states plainly which TURN evidence exists
  (17/17 protocol checks from the socket up) and which does not (a relay-only
  browser session).
- Published numbers re-derived from their artifacts: cold-load JavaScript
  126.7 → **127.3 KiB** gzip, initial 15 files 154.2 KiB gzip / 499.2 KiB raw,
  `src/app.js` 79.0 KiB gzip of 251.9 KiB raw, deferred graph 164.5 KiB, axe-core
  **469** passing rule results at 0 violations, inline critical block 37.5 KiB
  raw / 8.2 KiB gzip.
- Durability was re-measured and passes at every delay including an immediate
  reload; the earlier archived run that recorded a loss at 0 ms did not reproduce.
- The hero states its metric: "412 **of 420** tests runnable in your browser",
  because 412 is browser-eligibility and 420 is the suite total, and printing one
  number unqualified read as a contradiction of the other.
- `tools/measurements.js` publishes the evidence index, and the dashboard's
  published-measurement count is derived from it instead of being typed.
- `tools/brief-table.js` generates the README's "Against the brief" table from the
  module deck, the suite totals and a scan of the import graph, so the brief's own
  criteria are answered in one place and the verdict moves only when the build
  moves. `tools/check-docs.js` runs its `--check`.
- Two counts that no gate could see are now under a generator: `docs/ROADMAP.md`
  published 416 tests / 386 pass (the suite is 420 / 390) and the newest
  `CHANGELOG.md` entry published 389 pass / 411 browser-eligible. Both documents
  are now rewrite targets of `tools/test-count.js`, which previously could not see
  them.
- `types/*.d.ts` declared `identityMath()`, which no module in `src/` exports - and
  with no TypeScript in the repo nothing could compile that away. The declaration
  is gone, and `tools/check-types.js` now fails the gate if any published
  declaration stops naming a real export.
- The `accessibility audit (axe-core)` CI step has never passed, and now we know
  why: `tools/a11y.js` loads its engine from `.tools/vendor/axe.min.js`, `.tools/`
  is git-ignored, and a fresh checkout therefore died on ENOENT while every local
  run passed. The tool now provisions the pinned engine itself (axe-core 4.14.0,
  SHA-256 checked before the first rule runs) and records the version in
  `docs/reports/a11y.json`. This is also why the step looked identical to a real
  violation: the runner reports both as "exit code 1".
- The 60-minute memory soak was re-measured on this build, and it does not say
  what the archived run said. Heap after GC goes **1.51 → 2.82 MiB** (peak 3.64 at
  minute 54) and the minute-60 snapshot holds **more** nodes and memory than the
  minute-10 one - 118,637 over 8.93 MiB against 109,456 over 7.96. Section 3 of
  `docs/LOAD_CHAOS.md` is generated from the artifact, so the heading moved to
  *larger* by itself; what had to be found by hand were the three sentences inside
  the app that claimed the soak "finished smaller than it started", and the
  dashboard row that scored it **met** - the brief's target is "≤ 400 MB, no
  leaks", and this pair demonstrates the first half, not the second.
- The assistant tab was labelled `M9 SINGU AI` while M9 in the deck is the
  cross-cutting performance budget. It is now `SINGU AI (unscored)` and the
  accessibility artifact was re-recorded against the rename.
- Three sentences about the deployed origin - in the README's M8 row,
  `docs/SECURITY_REPORT.md` and `docs/DEPLOY.md` - claimed Trusted Types was
  enforced there. GitHub Pages sends no `Content-Security-Policy` header at all
  (`curl -sI` on the live URL prints only `Strict-Transport-Security`), so the
  policy that URL carries is the meta tag in `index.html`; the app's
  `trustedTypesActive()` only reports that the browser exposes the API. The
  wording now states what is delivered and leaves enforcement as the open
  question it always was.
- Tooling and documentation no longer name a third-party deploy helper that is
  not part of this project.

## What this release does not claim

- The memory soak no longer claims a leak was ruled out. The measured hour sits
  two orders of magnitude under the 400 MB target, but its snapshot pair grew
  between minute 10 and minute 60, so `docs/LOAD_CHAOS.md` section 3 reports
  growth the budget absorbs rather than a shrinking pair - and no second hour has
  been run, which is what a leak curve actually needs.
- VoiceOver (Safari/macOS) and TalkBack (Android/Chrome) have not been run. Only
  the NVDA 2026.2 pass is recorded.
- Trusted Types enforcement on this deployment is not measured. GitHub Pages
  sends no CSP header at all, so `require-trusted-types-for` reaches the browser
  only inside the meta policy in `index.html`, and the dashboard's chip reports
  that the browser exposes the `trustedTypes` API - which is a different claim
  from the policy gating a sink.
- There is no hosted TURN relay. `tools/turn-server.js` is a dependency-free
  reference relay run as a local dev process, and the relay-only browser session
  has never produced a passing artifact.
- The adversarial security pass is internal (22 checks). No third-party red-team
  or external pentest has been performed.
- No 10,000-session load rig exists; the relay figures are 1,000 simulated
  clients on one machine.
