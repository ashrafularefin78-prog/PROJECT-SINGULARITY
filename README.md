## Overview

An attempt at *The Impossible Website Challenge*: one page that behaves like an
operating system, a collaborative workspace, a game engine and a secure
messenger at once - with no framework or npm dependencies in the shipped bundle.
The C/C++ compiler optionally loads a self-hosted WebAssembly toolchain.

The CRDT, lightweight C interpreter, renderer, crypto composition, storage layer,
WebRTC mesh and DOM code are hand-written against browser APIs. Broad C/C++
compilation uses third-party Clang and standard-library assets, not the subset
interpreter. There is no bundler or transpiler.

## Installation and run

Anything that can serve static files works. Python is enough (Node is *not*
required anywhere in this project):

```bash
python3 tools/serve.py 5173
# -> http://127.0.0.1:5173/
```

**Demo video:** [docs/demo/demo.mp4](docs/demo/demo.mp4) — 15:19, 8.8 MiB,
recorded from the running app by `node tools/demo.js`. No narration: the script
in [docs/DEMO.md](docs/DEMO.md) is burned in as captions, beat by beat, and
`docs/reports/demo.json` lists which beats performed their interaction.

**Compiler:** open M2, choose C or C++, paste source, optionally select extra source/header
files and supply stdin, then compile and run. The first WebAssembly run loads about
18.4 MiB of compressed same-origin assets; subsequent runs can use the offline cache.
Source stays on the device. The bundled Clang 8.0.1 supports C through C11 and C++
through C++17 without exceptions, host files, networking or threads. The 32 MiB
program cap is separate from compiler working memory. Third-party licenses and
uncompressed integrity hashes are in `assets/toolchain/`. Choose the interpreter
for small C-subset examples without loading the toolchain.

**Live deployment:** <https://ashrafularefin78-prog.github.io/PROJECT-SINGULARITY/>
- the canonical URL, and the only one this project publishes. GitHub Pages cannot
send response headers, so what arrives there is the CSP carried as a `<meta>` tag
in `index.html`: enforced, but without the three directives the HTML spec forbids
in a meta policy (`frame-ancestors`, COOP, COEP). [`_headers`](_headers) carries
the full set for hosts that read it, and [docs/DEPLOY.md](docs/DEPLOY.md) states
exactly which protection is active where.

Subpath deployments still work, and the server can reproduce one locally, which
is exactly where absolute paths break:

```bash
python3 tools/serve.py 5174 --prefix /PROJECT-SINGULARITY
# -> http://127.0.0.1:5174/PROJECT-SINGULARITY/
```

Opening `index.html` straight from disk (`file://`) cannot work: browsers block
ES module loading on `file://` pages, so the shell stays empty by design. The
page detects this and shows a notice with the command above instead of pretending
to load.

`tools/serve.py` sends the production security headers locally (strict CSP,
Trusted Types, COOP/COEP), so the app is always exercised under the policy it
ships with. `_headers` carries the same policy for hosts that read it, and the
CSP also travels inside `index.html` as a meta tag for hosts that cannot send
headers at all.

## Technologies

| Layer | What this build uses |
|-------|----------------------|
| Platform | HTML5, CSS3, JavaScript ES modules, Web Workers, Service Worker |
| Browser APIs | WebGL2 + GLSL, WebCrypto, IndexedDB, WebRTC, BroadcastChannel, CompressionStream, Trusted Types |

| Tooling and delivery | Python 3 standard library, Node only for measurement, GitHub Actions, GitHub Pages static hosting |

No React, no bundler, no npm package imported by `src/`, and no AI service. The
intelligence in this project is local: a compiler, a CRDT and a renderer. That is
a deliberate constraint rather than a missing feature - it is what keeps the page
working offline and free of third-party connections. The only Python is tooling;
the shipped page is static HTML, CSS and ES modules.

### Development dependencies

The shipped page needs nothing beyond a browser. The *tooling* does have an
environment, stated plainly: Python 3 (dev server, deploy build, critical-CSS
inliner), Node 24 for the test runner and the measurement drivers -
`python3 tools/bootstrap-node.py` fetches a portable copy into `.tools/`, which
is git-ignored, so nothing is installed system-wide - a Chromium-family browser
for the headless runs (pointed at it with `BROWSER_PATH`), and ffmpeg only if
you want to re-record the demo video. Nothing from npm is ever installed into
the project.

## Features - what is real, and what is not

| Module | Status | Notes |
|--------|--------|-------|
| M1 Collaborative editor | **Full** | Own RGA CRDT, live cursors, per-user undo, offline merge, cursor-indexed lookups (20k sequential appends visit zero nodes), watermark-bounded tombstone collection and op-log trimming. Interior tombstones are kept by design. The retained op log is also a second execution path: the M1 temporal core replays any prefix into a fresh replica, fingerprints the visible state (character ids, order and text) and proves that forward, reversed and shuffled merges agree. |
| M4 End-to-end encryption | **Full** | X3DH + Double Ratchet + safety numbers + group epochs + streaming file AEAD. The signed prekey bundle is verified *inside* the handshake, before any key material exists. |
| M6 Offline-first storage | **Full** | IndexedDB op log, snapshots, quota, migrations, and a service worker whose paths are scope-relative - offline is verified by stopping the server and reloading under `/PROJECT-SINGULARITY/`. |
| M2 In-browser C/C++ runtime | **Partial** | Self-hosted Clang 8.0.1/WASI compilation plus a separate lightweight C-subset interpreter, worker sandbox, terminal and kill switch. Includes ternary, switch/fall-through, structs (nested, arrays, by value, heap-linked lists), casts, do/while, `malloc`/`calloc`/`realloc`/`free`/`memcpy`/`memset` over a bounds-checked arena, `scanf`/`sscanf`, plus the library surface student C actually uses: `<string.h>` (`strcpy`, `strcat`, `strcmp`, `strncpy`, `strchr`), `<ctype.h>` (`toupper`, `isdigit`, `isalpha`), `<math.h>` (`sqrt`, `pow`, `fabs`), `#define` constants, function-like macros (`#`, `##`, `__VA_ARGS__`), `typedef`, `int m[2][3]`, function pointers and unions. The bounds-checked arena fails closed - an overflowing `strcpy` is an error, never silent corruption. Three layers read that C for defects: `src/runtime/hardening.js` audits the source and names 13 defect classes with their CWE tags, but only where the source proves them, and ships the list of what it refuses to guess as `NOT_CHECKED`; `src/runtime/sanitizer.js` watches one execution for the four cases a run cannot show - a read through a released handle, a block freed twice, a stale handle passed on, a heap byte printed before anything wrote it - and moves no value the program can see; and the arena bounds every write either way, which is why the audit's silence is not an unguarded path. Six vulnerable/fixed pairs in `src/runtime/hardening-samples.js` show each class with a working fix, every claim beside them measured by the suite, and the autopilot blocks on an error-severity finding rather than softening it into a hint. The separate WebAssembly mode uses real Clang and C/C++ standard libraries, supports extra source/header files and runs locally in a killable worker. The interpreter remains a C subset. The pinned sysroot ships no `<stdatomic.h>` and the Clang 8.0.1 WASI backend has no atomics feature, so the C11 atomic API is installed from an in-repo overlay into the virtual filesystem as `volatile`-scalar statement expressions - real C11 source on this backend, single-threaded by construction and not lock-free for a threaded target. Constructs the backend cannot code-generate (`_Atomic`, `__sync_*`/`__atomic_*`/`__c11_atomic_*`, C++ `std::atomic`) and C++ `throw` are refused with a named diagnostic carrying the file, line and column instead of an LLVM selector dump. WebAssembly programs have no host filesystem, networking, native GUI or thread access; C++ exceptions, arbitrary native libraries and standards beyond C11/C++17 are unavailable. |
| M3 3D engine | **Partial** | WebGL2 instancing to 100k, a real PCF shadow map, 1M GPU particles, and physically based shading (Cook-Torrance GGX/Smith/Schlick, Reinhard tonemap). A glTF 2.0 loader (`src/graphics/gltf.js`) parses JSON and GLB binary, materialises accessors, images, samplers and textures, flattens TRS node hierarchy into world-space transforms, computes mikkelsen tangents, generates flat normals when absent, and parses skins, `JOINTS_0`/`WEIGHTS_0`, looping clips with LINEAR/STEP/CUBICSPLINE, and up to four morph targets per primitive with position/normal deltas and animated weights; the M3 panel fetches `assets/models/singularity-core.glb` (generated by `tools/make-sample-glb.py`) and `assets/models/skinned-totem.glb` (generated by `tools/make-skinned-glb.mjs`), which carries two morph targets and a CUBICSPLINE weights track, uploads each primitive and draws it through the same BRDF. 29 tests cover the full parsing surface including skin and morph validation and both animation samplers. Image-based light is band-2 SH for diffuse plus a six-level GGX-importance-sampled specular prefilter chain uploaded as explicit mip levels and sampled at `roughness * 5`, with the split-sum Fresnel term read from a 64x64 RG16F BRDF integration LUT computed at boot; the measured HDRI probe rebuilds both cubes, with peak, mean and SH reconstruction error against the analytic source shown in the panel. The totem's seven-joint, six-second clip is evaluated by `src/graphics/skin.js` and blended four joints per vertex from an RGBA32F bone texture refreshed once per frame, so joint count is not capped by the uniform budget; morph deltas are applied before skinning in both the colour and depth passes. *No WebGPU (an explicit non-goal in [docs/NON_GOALS.md](docs/NON_GOALS.md)); TANGENT/UV morph deltas, more than four targets per primitive and non-joint node animation are refused, not half-implemented.* |
| M5 Peer mesh | **Partial** | Three carriers into one mesh: BroadcastChannel for tabs, WebRTC data channels for separate machines (copy-pasted invite/answer codes with no server; STUN on by default; ICE restart on `disconnected` after 2 s with `iceRestart:true`, completed by `acceptRestartAnswer()` without tearing down the data channel), and a ciphertext relay carrier (`src/collab/relay.js`) for peers that share neither: frames are sealed with an HKDF room key, queued in a sender outbox, re-posted to the next node in a URL list when a node stops answering, and deduplicated by sealed frame id at the receiver. The node (`tools/relay.js`) implements the same envelope contract; it was driven at 1,000 clients, killed mid-backlog (`SIGKILL`, 20,000 pending, all replayed from the log, 256 ms outage), and killed for good in a failover run where the dead node's whole backlog was re-posted from the client outboxes to a standby node — 0 lost, 0 duplicated. The app-to-node path itself runs in a real browser under the shipped CSP (`tools/relay-e2e.js`). [LOAD_CHAOS.md](docs/LOAD_CHAOS.md), section 12. *No hosted TURN relay: a dependency-free reference one ships as `tools/turn-server.js`, the panel has a relay-only ICE switch, and both layers are gated (`tools/turn-selftest.js` at the protocol level, `tools/turn-relay-e2e.js` in a real browser) - so a symmetric NAT is a documented path rather than an advice note, but relay bandwidth is still somebody's server. The node is a dev-server mount today, not a deployment.* |
| M7 Accessibility | **Partial** | Semantics, keyboard model, live regions, text alternative tree, motion/contrast/scale/RTL/visual-effects preferences. ### SINGU AI (unscored, outside the scored eight)

The page also ships **SINGU AI**, a local C engineer in the SINGU AI tab. It is not a
language model and makes no network calls. Two engines share one brief: the
**composer** (`compose.js`) joins 47 everyday blocks over integer arrays, text,
3x3 matrices and scalar N - sums, medians, sorts, searches, palindromes, Caesar
shifts, run-length encoding, matrix products, primes, factorials and more - into
one program when the brief asks for several steps, and computes each expected
output line independently in JavaScript; the **systems catalogue** (`singu.js`)
keeps 15 hand-written patterns across three levels (low-level bits and bytes,
advanced heap structures, expert allocators, pools, wire formats, an SPSC queue
shape and a register map). The **planner** (`planner.js`) picks the stronger
match, the **autopilot** (`autopilot.js`) runs every acceptance input in the M2
interpreter, compares the trace with those independent expectations, and applies
only repairs it can justify - a missing include, a missing semicolon, one
unmatched brace, an undeclared first use in main, a unique one-edit call typo.
Anything else stops with the interpreter's own diagnosis. The **explainer**
(`explain.js`) walks the parser AST and reports functions, loop nesting,
recursion, heap calls, globals and unsafe constructs. Five suites hold 59 tests
against that contract, including every emitted program compiled and run in the
sandbox. Nothing outside the M2 C subset is emitted, and a brief that neither
engine recognises is reported as a weak match instead of being answered with
invented code.

## Usage - try the interesting bits

- **Two tabs, one document.** Open the app twice; both edit the same CRDT over
  BroadcastChannel and merge live.
- **Across two machines.** In M5, create an invite code in one browser and paste
  it into another: an answer code comes back and a data channel opens directly
  between them. No server is involved at any point.
- **Airplane mode.** In M1, go offline, keep typing, then go online: a full-state
  sync merges everything with no lost characters.
- **Kill an infinite loop.** In M2, load the infinite-loop sample and run it.
- **Write real C.** The M2 sample builds a linked list with `malloc` and `->`,
  switches on a grade, asks for two integers with `scanf`, then echoes stdin.
- **Ask SINGU AI for C.** In the SINGU AI panel, type a brief such as *a lock-free
  single-producer queue*, *an arena allocator* or *the sum of the numbers and
  sort ascending*, pick a level if the brief does not name one, then **Generate
  C** and **Build & run**. **Autopilot** runs the built-in acceptance inputs and
  repairs only what it can justify; **Explain C** reports the program's
  functions, loops, recursion and heap use. The plan and the hazards list sit
  beside the code; **Send to M2 runtime** hands an edited program over.
- **Prove the relay is blind.** In M4, send a message and read the relay
  inspector - every field it can see is listed.
- **Watch a tombstone disappear.** In M6, press *Compact*: the panel reports how
  many tombstones were collected, how many ops were trimmed, and which watermark
  allowed it.
- **Max out the engine.** In M3, push instances to 100,000 and particles to
  1,000,000: 4 draw calls, and the FPS readout is the real frame rate (58 FPS on
  the machine this was measured on - see LOAD_CHAOS.md).
- **Open the module dial.** Press the backslash key for the ring: all eight modules on a
  radial dial, each showing the score it is actually carrying, with arrow keys
  to turn, digits to jump straight to one, Enter to open and Escape to close.
- **Watch the deck.** The strip under the tabs plots live activity - frame rate
  while the engine runs, document operations per second otherwise - and the
  ticker beside it reads real numbers, not decoration.
- **Drive it from the keyboard.** **Ctrl/Cmd + K** opens the command palette from
  anywhere: module jumps, the offline toggle, virtual peers, log compaction,
  persistent storage, the clipboard, and every accessibility preference. Each
  command calls the same function its button calls, so there is no second
  implementation to drift. **Alt + 1...8** jumps straight to a module (the number
  matches its tab label).
- **Switch the future off.** In M7 set *Visual effects* to **Off**: the aurora,
  scanlines, sweeping light and perspective floor disappear and nothing else
  changes, because they are decorative layers painted under a flat layout. The
  telemetry strip in the header keeps reporting regardless.
